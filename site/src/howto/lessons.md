# Lessons that should transfer

The rest of this section argues from the record. This page collects the claims, with the evidence and a note on adapting each one, so that someone with a different project can take the shape and leave the specifics. The specifics were a farming fantasy written in ten days by someone comfortable with a terminal. The shape should survive being moved.

**Voice is the highest-leverage decision and it comes first.** The project spent its first day and a half on register with no story in sight, and the register it chose is still the book's. Evidence: the [first session](../transcripts/0c653b33-1efd-45bb-b7ab-26ed3dca981e.md), whose pre-premise stretch is shown in full. To adapt: whatever your medium, spend the first session on how the output should sound or look, using throwaway subject matter, before you say what it is about.

**Examples outrank rules, and the model must read the examples first.** Drafting from rules alone produced compliant, generic prose. Drafting from exemplars produced the voice. Evidence: the [voice memo page](../workflow/voice-and-exemplars.md) and the voice-drift incident on 24 and 25 August. To adapt: keep a small set of outputs you actually like, protect them, and make reading them the first instruction in every session.

**Feedback should name what the reader felt, and then become a rule.** The dialogue blind tests came from "this feels artificial" and ended as countable per-character constraints. Evidence: [27 August](../chronicle/2026-08-27.md). To adapt: report effects, ask for causes, and end every round by having the general finding written into a file.

**Anything not in a file did not happen.** Sessions have no memory. The handoff document, the pointer file and the dated rulings exist because of this. Evidence: the [handoff page](../workflow/next-md-handoff.md) and the fact that the last session of the project started by reading the queue the previous one left. To adapt: keep a short root instructions file and a living next-steps file from the first day, and update the second at the end of every session.

**The model will fabricate facts about its own earlier work, and only a tool will notice.** The citation checker found 206 mismatches between notes and manuscript, 110 of them quotations that never existed, in a set of notes that read perfectly well. Evidence: [28 August](../chronicle/2026-08-28.md). To adapt: any claim the model makes about what it previously produced, quotations, summaries, "as established in chapter three", should be mechanically checkable, and periodically checked.

**Check the whole corpus, not just the current piece.** Both major discards were caused by properties of the whole that no per-scene check could see: drift across a book and echo across drafts. Evidence: the [overlap checker](../workflow/overlap-checking.md) and the [30 August](../chronicle/2026-08-30.md) discard. To adapt: build at least one tool that reads everything you have produced and asks about repetition, drift and similarity to things you rejected.

**Cheap and narrow, then careful and broad.** The recurring structure in the project's checks is a fan-out of small model calls each asking one question, followed by one larger model judging the results. It was cheaper than one big pass and, on the project's own seeded tests, not worse at finding problems. Evidence: the [linting page](../workflow/llm-tells-and-linting.md). To adapt: never ask one call to find everything. Give each reviewer one question and give one reviewer the job of deciding.

**Expect to discard, and make discarding cheap.** Two drafts of book one were thrown away. The knowledge from each was in the rule files before the draft went. Evidence: the [throwing away page](throwing-away.md). To adapt: version control, exemplars stored apart from drafts, and the habit of extracting the rules a bad draft reveals before deciding its fate.

**Keep creative work in one long conversation and delegate the bounded work.** Splitting drafting across agents lost coherence. Splitting checks across agents gained speed and fresh eyes. Evidence: the [delegation page](delegation.md). To adapt: the test for delegating a task is whether it can be fully described in a brief and its result fully described in a report. Drafting fails that test. Checking passes it.

**Earn autonomy in steps.** Supervision went from scene by scene to batches to unattended over four days, and the unattended runs had a written stopping rule. Evidence: [31 August](../chronicle/2026-08-31.md) and [2 September](../chronicle/2026-09-02.md). To adapt: loosen one notch at a time, on evidence, and never leave the model alone without telling it when to stop.

**Ask the model to catch itself, and mean it.** The model stopped mid-draft to flag contamination risk, and retracted a set of results when its scoring method proved unreliable. Both followed clear instruction that surfaced problems were wanted. Evidence: [the loop page](the-loop.md). To adapt: put it in the standing instructions, and when the model stops to tell you something is wrong, treat that as the process working rather than as a delay.

One last thing the record shows, which is less a lesson than a warning. The parts of this project that were planned up front were the parts that changed most. The five-book plan, the first draft, the first set of voice rules. The parts that lasted were the ones that came out of a specific failure and were written down with the failure attached. If you are starting something like this, plan lightly, read closely, and keep the files.
