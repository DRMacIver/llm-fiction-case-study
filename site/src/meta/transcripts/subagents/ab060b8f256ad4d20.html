Problem: tools/render.py embedded transcript prose (user prompts, assistant text, thinking) as HTML-escaped but otherwise raw markdown, so mdBook never rendered lists/bold/tables/code fences — they showed as literal **, - , backticks, etc.

Fix (tools/render.py):

  • New render_markdown(text): renders with MarkdownIt("commonmark", {"html": False, "breaks": True}).enable("table") — html: False means any raw HTML in the (untrusted) source is escaped as literal text rather than passed through, so <script> etc. can't execute. Markdown is rendered first, then the [[...]] redaction markers are converted to <span class="redacted"> on the rendered HTML (markers survive markdown rendering unchanged since they contain no markdown syntax chars). Tables get wrapped in <div class="table-wrap"> for horizontal scroll.
  • Critical fix: mdBook/pulldown-cmark's raw-HTML-block detection ends at the first blank line, and fenced code blocks / loose lists in the rendered markdown can contain internal blank lines — this was silently breaking the raw-HTML embedding for several transcripts (tags spilling out as literal <ul>, <li>, etc., confirmed via mdbook build warnings on 3 files). Fixed by replacing internal blank lines with an invisible zero-width space (U+200B) before embedding.
  • render_turn() now calls render_markdown() for user text, assistant text, and thinking blocks instead of the old escape-and-<br> approach. Tool-use summary lines are untouched (still plain esc_inline).
  • SUBAGENT_STYLE (standalone subagent pages) and site/theme/custom.css (mdBook theme) both got matching pre/code/table/.table-wrap CSS (light-grey background, monospace, overflow-x: auto).
