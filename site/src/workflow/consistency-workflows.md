# Workflows and subagents for consistency checks

Most of the individual checks described elsewhere on this site (canon consistency, farming facts, the language-police pass) are defined as Claude Code "skills," reusable instruction sets a session can invoke on demand. Run one at a time on the chapter currently being drafted, a skill is a normal part of an interactive session. Run across every accepted chapter at once, checking a whole book's consistency in one sweep rather than one chapter at a time, the same checks need something more structured: a scripted workflow that fans work out across many subagents and collects the results, without a person watching each individual check happen.

## Why this needed its own workflow

A single session, even with a skill loaded, checks one thing against a manageable amount of context at a time. Asking whether one chapter is consistent with everything established before it is a check of that shape. Asking whether a whole book of them is internally consistent is that same check run dozens of times against a canon that keeps changing as earlier findings get resolved, which is a different kind of task: less about depth of judgement on any one chapter and more about coverage across all of them.

David asked directly for this shape of tool partway through the project: a workflow that runs a bounded, cheaper model against each chapter individually, hunting for inconsistencies, rather than a single expensive pass trying to hold the whole book in mind at once. The reasoning matches the same cost and reliability tradeoff that shows up in the language-police pass: a smaller model doing narrow, well-specified work across many chapters in parallel, followed by a synthesis step reconciling what came back, tends to be both cheaper and more thorough than one large context window doing everything serially. The session where this was specified and built is the clearest record of the reasoning behind it: [2026-08-27, building a consistency-check workflow](../transcripts/3ef92e14-71be-4557-a7d1-f251a7410081.md).

## How the pieces fit together

The consistency-check skill itself defines the actual judgement: read a chapter, check its claims against canon in priority order (hard facts and continuity first, softer thematic consistency last), and report contradictions, or the weaker "drift" category where a claim is technically compatible with canon but strains it under the weight of what's already been established. A workflow wrapping this skill assigns one subagent per chapter, running these checks in parallel rather than one after another, and then a further step gathers every subagent's findings into a single report rather than leaving David to read through dozens of separate outputs.

This division of labour, one shallow parallel pass followed by one deeper serial synthesis, recurs enough in this project that it's worth naming as a pattern rather than treating each instance as a one-off. It shows up in the language-police pass's fan-out of lens agents feeding one aggregating judge, in the per-scene editing pipeline's four parallel lenses feeding one synthesiser, and here, in per-chapter consistency subagents feeding one workflow-level report. In each case the parallel step is cheap and narrow, and the serial step is where genuine judgement, including the judgement about which findings actually matter, happens.
