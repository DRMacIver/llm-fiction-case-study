# llm-fiction-case-study

Source for <https://drmaciver.github.io/llm-fiction-case-study/>, a site describing how David R. MacIver wrote the Royal Road novel [How to Save the World](https://www.royalroad.com/fiction/189685/how-to-save-the-world) with Claude Code over ten days in August and September 2026.

Everything on the site, including every page of prose and this README, was generated by Claude. David set the direction and the redaction rules and read the results. The site says this about itself on every entry point, and the repository is published partly so that claim can be checked.

## What is in the site

- **How to do this yourself**: the practical section. Setting up Claude Code, choosing a voice before a story, how the back and forth between author and model actually went, which files the model was told to keep, turning feedback into checks, throwing drafts away, delegation, and the lessons that should transfer.
- **The workflow**: the tooling and rule system of the novel project, one page per feature.
- **Chronicle**: a day by day account reconstructed from the novel repository's git history and the session transcripts.
- **Transcripts**: the Claude Code sessions themselves, redacted for spoilers and rendered with tool calls simplified and file contents suppressed.

## How the site is built

The novel lives in a separate private repository. Its Claude Code session transcripts are read in place from the local `~/.claude/projects` directory and are never copied here. A four-stage Python pipeline turns them into pages:

```
uv run python tools/parse_transcripts.py            # raw JSONL -> build/parsed/ (tool calls simplified, no file contents)
uv run python -c "from tools.prose_index import main; main()"   # shingle index of unpublished story text, from files and git history
uv run python tools/redact.py                        # spoiler terms, topic sentences, quoted unpublished prose, private info -> build/redacted/
uv run python tools/render.py                        # markdown and HTML pages under site/src/transcripts/
mdbook build site
```

`tools/spoilers.json` holds the redaction rules: term lists, topic patterns, the published-scene boundary, and the timestamp before which nothing is redacted because the story premise had not yet been introduced. `tools/FORMAT_NOTES.md` documents what was learned about the transcript format. Redaction markers deliberately do not say what category of thing they removed, since the reason would itself be a spoiler.

Only the rendered, redacted output under `site/src/transcripts/` is committed. `build/` is not. GitHub Pages deploys from `site/book` on every push to `main` via `.github/workflows/pages.yml`.

Tests run with `uv run pytest`.

## Checking the writing

The prose pages were fact-checked and consistency-checked against the transcripts, the novel's git history and the Claude Code documentation by a multi-agent workflow. `fact-check.md` records every claim, its receipt and verdict, the problems found and how each was resolved. The procedure is written up as a reusable Claude Code skill in `.claude/skills/writing-check/SKILL.md`.

## Redaction policy in brief

Published chapters are scenes 1 to 40 of the novel. Anything about the story beyond those, plus a small set of hard spoilers, is removed. File contents written or read by the model are never shown after the premise was introduced. Private paths, identifiers and addresses are removed throughout. The full policy is on the site's About page. If you spot a leak, please open an issue rather than quoting it.
